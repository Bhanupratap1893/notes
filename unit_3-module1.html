Introduction to Zenmap

1.1

📖 What is Zenmap?

Zenmap is the official graphical user interface (GUI) for Nmap (Network Mapper). Developed by Gordon Lyon (Fyodor) and the Nmap Project, it makes Nmap's powerful features accessible through a visual interface rather than the command line. Zenmap is free, open-source software distributed under the Nmap Public Source License.

Nmap was originally created in 1997 and has since become the de facto standard for network discovery and security auditing. Zenmap, the GUI companion, translates visual inputs (clicking scan options) into actual Nmap command-line arguments, executes them, and displays results in a graphical dashboard.

  • Full name: Zenmap Network Scanner (GUI frontend for Nmap)
  • Developer: Gordon Lyon (Fyodor) / Nmap Project
  • License: Open Source — Nmap Public Source License
  • Platform: Windows, Linux, macOS (cross-platform)
  • Language: Python (PyGTK for UI)
  • Pre-installed: Kali Linux, Parrot OS
📌 Definition

Zenmap = GUI wrapper for Nmap. It converts visual selections into Nmap commands and displays results graphically — including a network topology map showing connected devices.

🎯 Exam Point

Nmap was created in 1997 by Gordon Lyon (Fyodor). Zenmap is its official GUI. Zenmap does NOT add new capabilities — the underlying Nmap engine does all the scanning.

Network Discovery

1.5

🌐 What is Network Discovery?

Network Discovery is the process of identifying all active devices on a network. Before scanning ports or services, we need to know which IP addresses have live machines behind them. This is the first phase of any network audit or penetration test.

Techniques used:

  • ICMP Ping Sweep: Send ICMP echo requests to each IP — alive hosts reply
  • ARP Scanning: Use ARP requests on local subnet — most reliable for LAN
  • TCP/UDP Probes: Send TCP SYN or UDP packets to detect hosts that block ICMP
  • DNS Resolution: Resolve hostnames of discovered IPs for extra info
bash — Network Discovery Commands 
# Ping sweep — discover all live hosts in subnet (no port scan)
$ nmap -sn 192.168.1.0/24

# ARP scan — fastest for local network, requires root
$ sudo nmap -sn -PR 192.168.1.0/24

# TCP SYN ping — useful when ICMP is blocked by firewall
$ nmap -sn -PS80,443 192.168.1.0/24

# Discover hosts with aggressive mode (OS + version + scripts)
$ sudo nmap -T4 -A -v 192.168.1.0/24

Network Discovery = Colony mein roll call! Jaise class teacher attendance leti hai — "Rahul?" "Present!" "Priya?" "Present!" "Mohan?" ... silence (absent). Waise hi Nmap har IP address ko ping karta hai. Jo device hai woh reply karta hai, jo nahi hai woh chup rehta hai!

⭐ Important Points

  1. -sn flag = "Scan No-ports" — only host discovery, no port scan.
  2. ARP scanning works only on local subnet — cannot cross routers.
  3. CIDR /24 = 254 usable host addresses (256 - 2 for network and broadcast).
  4. Network discovery is the reconnaissance phase of penetration testing.
  5. TCP SYN ping (-PS) is useful when ICMP ping is blocked by firewall.

🇮🇳 Port Scanning — Hinglish

Port scanning = Building ke darwazon ki jaanch! Computer ek building hai, 65535 darwaze (ports) hain. Nmap chowkidar ki tarah jaata hai aur har darwaza thokta hai — "Koi hai?"

Open: "Haan ji, main yahan hoon!" (service chal rahi hai)

Closed: Darwaza milta hai but andar koi nahi (port accessible, service nahi)

Filtered: Koi firewall uncle darwaze ke bahar khade hain — packet hi nahi pahunchne deta!

SYN Scan ka jadoo: Yeh "stealth" scan hai — poora handshake nahi karta. Jaise kisi ka darwaza knock karo aur foran peeche hat jaao — door open hua ki nahi pata chal gaya, but andar nahi gaye! Most IDS systems ise log nahi karte!

⭐ Important Points

  1. Total ports: 0 to 65535 — well-known ports are 0-1023.
  2. -sS (SYN scan) is the default scan — fast, stealthy, requires root.
  3. -sT (Connect scan) doesn't need root but is logged by target.
  4. -p- scans all 65,535 ports. -F scans only top 100.
  5. Port 3389 (RDP) exposed to internet = major security risk.
  6. UDP scan (-sU) is much slower than TCP — often overlooked by beginners.
Q: What is the difference between SYN scan (-sS) and Connect scan (-sT)? ▼
SYN Scan (-sS): Sends a TCP SYN packet. If the port is open, receives SYN/ACK, then immediately sends RST (reset) to abort the connection — never completing the 3-way handshake. Hence called "half-open" or "stealth" scan. Requires root privileges. Less likely to be logged. Connect Scan (-sT): Completes the full 3-way TCP handshake (SYN → SYN/ACK → ACK). Does not need root privileges. However, the target application and OS logs the connection, making it more detectable.
Q: What does a "filtered" port state mean in Nmap results? ▼
A filtered port state means that a firewall, packet filter, or network obstacle is blocking Nmap's probe packets from reaching the port. Nmap cannot determine whether the port is open or closed. The probes are simply dropped or an ICMP unreachable error is returned. This is different from "closed" (port reachable but no service) and "open" (service actively listening).

Service Detection

1.8

🔧 What is Service/Version Detection?

Service detection (also called version detection, enabled by -sV) goes beyond finding open ports. It identifies:

  • Application name: Apache, nginx, OpenSSH, MySQL, etc.
  • Version number: Apache 2.4.51, OpenSSH 8.4p1, MySQL 8.0.27
  • Protocol details: HTTP/1.1 vs HTTP/2, SSL version, cipher suites
  • Extra info: OS hints, build flags, platform details

This information is critical because specific versions may have known CVE (Common Vulnerabilities and Exposures). Example: Apache 2.4.49 has CVE-2021-41773 (path traversal + RCE).

bash — Service / Version Detection 
# Version detection
$ nmap -sV 192.168.1.100

# Aggressive version detection (intensity 9 = maximum probing)
$ nmap -sV --version-intensity 9 192.168.1.100

# Full aggressive scan: version + OS + scripts + traceroute
$ sudo nmap -A 192.168.1.100

Service detection = Shop ke baare mein details! Port scan se pata chala ki darwaza 80 khula hai — lekin andar kaunsi dukaan hai? Service detection se pata chalta hai: "Andar Nike ka store hai, aur 2019 season ki collection chal rahi hai!" (Apache 2.4.51 running hai!)

-A flag: Ek hi command mein sab kuch — version detection + OS detection + NSE scripts + traceroute. Jaise ek form mein saari information ek saath bhar do!

  1. -sV flag enables service/version detection.
  2. --version-intensity 0-9 — higher = more probing = more accurate but slower.
  3. -A flag combines version + OS detection + scripts + traceroute.
  4. Version info is used to find CVE (Common Vulnerabilities) in specific software versions.
  5. Nmap uses nmap-service-probes database for version identification.

Operating System Detection

1.9

🖥️ How OS Detection Works — TCP/IP Stack Fingerprinting

Different operating systems implement the TCP/IP stack with slight differences in behavior. Nmap sends a series of specially crafted packets and analyzes responses to identify the OS. Key indicators:

  • TTL (Time To Live): Linux=64, Windows=128, Cisco=255, Solaris=255
  • TCP Window Size: Different defaults per OS
  • IP ID Sequence: How the OS generates packet IDs
  • ICMP response characteristics
  • TCP options supported and their ordering
  • TCP timestamp behavior

🇮🇳 OS Detection — Hinglish

OS detection ek voice recognition ki tarah hai! Jaise aap phone pe "Hello" sunke pehchaan sakte ho ki Sachin hai ya Virat — aise hi har OS ki network "awaaz" (TCP/IP behavior) alag hoti hai!

TTL trick: Ek quick method — agar reply ka TTL 64 hai → probably Linux. TTL 128 → probably Windows. Experienced pentesters yeh shortcut regularly use karte hain!

--osscan-guess: Jab Nmap 100% sure nahi hai toh yeh flag use karo — Nmap best guess deta hai percentage confidence ke saath. Jaise doctor bina test ke symptoms dekh ke 80% probability bolte hain!

⭐ Important Points

  1. OS detection uses TCP/IP stack fingerprinting technique.
  2. -O flag enables OS detection — requires root privileges.
  3. TTL of 64 → Linux/Unix/Android. TTL of 128 → Windows.
  4. OS detection needs at least one open AND one closed port to work accurately.
  5. --osscan-guess provides best-effort guess with confidence percentage.
  6. Nmap uses the nmap-os-db database with thousands of OS fingerprints.
Q: How does Nmap detect the operating system? What is TCP/IP fingerprinting? ▼
Nmap's OS detection uses TCP/IP stack fingerprinting. Different operating systems implement the TCP/IP stack with subtle differences. Nmap sends a series of up to 16 specially crafted probes (unusual TCP flags, ICMP requests, etc.) and analyzes the responses. It examines: TTL values (Linux=64, Windows=128, Cisco=255), TCP window sizes, IP ID sequences, ICMP response characteristics, TCP options ordering, and timestamp behavior. These fingerprints are compared against the nmap-os-db database containing thousands of known OS fingerprints to identify the target OS.

💡 Timing Template Explained

The -T flag (0-5) controls scan timing: T0=Paranoid (IDS evasion, very slow), T1=Sneaky, T2=Polite, T3=Normal (default), T4=Aggressive (recommended), T5=Insane (may miss results). For ethical hacking labs, -T4 provides the best balance.

🇮🇳 Scan Profiles — Hinglish

Scan profiles = Washing machine ke modes! Quick Wash (15 min) = Quick Scan. Normal Wash = Regular Scan. Heavy Duty + Steam = Intense Scan (sab kuch pata karo!).

-T flag = Machine speed setting: T1 = Dheere dheere (chor jaisi chupke chupke), T4 = Fast and furious, T5 = Turbo mode (itna fast ki kuch results miss bhi ho sakte hain)!

Practical tip: Exam ya lab mein -T4 use karo — fast bhi hai, accurate bhi. Production network pe -T3 (default) use karo — network pe load kam rahega.

⭐ Important Points

  1. Timing templates -T0 to -T5 control scan speed and aggressiveness.
  2. Ping Scan (-sn) = fastest — just checks which hosts are alive.
  3. Intense Scan (-T4 -A -v) = most detailed single-host analysis.
  4. Custom profiles can be created in Zenmap's Profile Editor.
  5. -T3 is the default timing if no -T flag is specified.
  6. Never use -T5 on production networks — may overwhelm target services.

Hidden SSID Detection

3.6

👁️ How Kismet Finds Hidden Networks

A hidden SSID (also called "non-broadcasting" or "cloaked") is a network configured to omit its SSID from beacon frames. Kismet reveals hidden SSIDs because:

  1. When any client tries to connect → sends probe request containing the SSID
  2. AP sends probe response with SSID
  3. During association handshake — SSID appears in frames
  4. Kismet captures ALL these frames → hidden SSID revealed!
⭐ Critical Security Concept

Hidden SSID is NOT a security measure! It is "security through obscurity." Kismet, Wireshark, airodump-ng, and many other tools reveal hidden SSIDs within seconds of any client connecting. Real security = strong WPA3 encryption + strong passphrase, not hiding the network name.

🇮🇳 Hidden SSID — Hinglish

Hidden SSID = Naam chhupa diya, kaam nahi! Socho kisi ne school mein attendance se bachen ke liye naam change kar liya — lekin teacher ne class photo se pehchaan liya!

Waise hi — network ka naam chhupa diya broadcast mein. Lekin jab bhi koi device connect karta hai, woh network se naam poochta hai — yeh conversation pakad ke Kismet hidden SSID reveal kar deta hai! Naam chhupana security nahi hai — asli security WPA3 + strong password hai!

⭐ Important Points

  1. Hidden SSID only hides the network name from casual users — not security professionals.
  2. Kismet reveals hidden SSIDs by capturing probe request/response frames during connection.
  3. Hidden SSID is NOT a security feature — provides false sense of security.
  4. Any client connecting to hidden network exposes the SSID in its probe requests.
  5. Real security comes from WPA2/WPA3 with strong passphrase, not SSID hiding.

Rogue Access Point Detection

3.7

🚨 What is a Rogue Access Point?

A Rogue Access Point (Rogue AP) is an unauthorized wireless access point installed on a network without administrator knowledge. Types:

  • Malicious Rogue AP (Evil Twin): Attacker sets up AP with same SSID as legitimate AP to intercept traffic
  • Accidental Rogue AP: Employee plugs in personal router creating unauthorized network
  • Misconfigured Rogue AP: Legitimate AP with wrong security settings

Kismet detects rogue APs by:

  • Comparing against authorized AP whitelist (configured by admin)
  • Alerting on same SSID + different BSSID (classic Evil Twin indicator)
  • Detecting APs on unexpected channels
  • Flagging APs with unusual vendor/MAC combinations

🇮🇳 Rogue AP — Hinglish

Rogue AP ka best example: Coffee shop Evil Twin attack! Tum cafe mein ho, "CafeWiFi" naam ka network dikh raha hai — connect ho gaye. Lekin agar kisi hacker ne nearby apna hotspot "CafeWiFi" naam se setup kiya ho — tum actually hacker ke network se connected ho! Hacker tera sara internet traffic dekh sakta hai!

Kismet aise cases detect karta hai — agar 2 APs same SSID "CafeWiFi" broadcast kar rahe hain alag-alag BSSID (MAC address) se — yeh suspicious hai! Alert milega: "Same SSID, different BSSID detected — possible Evil Twin attack!"

⭐ Important Points

  1. BSSID = MAC address of Access Point — unique per physical device.
  2. Same SSID + different BSSID = primary Evil Twin indicator.
  3. Kismet compares against authorized AP whitelist to detect rogue APs.
  4. Rogue APs can be malicious (Evil Twin) or accidental (employee's personal router).
  5. Enterprise systems like Cisco Meraki use similar rogue AP detection technology.

Incremental Mode

4.8

📈 Understanding Incremental Mode

Incremental mode is JtR's brute force mode. It tries all possible character combinations systematically, starting from shortest to longest. Unlike a pure brute force that goes a,b,c,d... aa,ab,ac... JtR's incremental mode uses frequency analysis — it tries more likely characters first based on statistical analysis of real passwords, making it smarter than pure brute force.

Built-in incremental modes:

  • All — All printable ASCII characters (95 chars)
  • Alnum — Alphanumeric only (62 chars)
  • Alpha — Alphabetic only (52 chars)
  • Lower — Lowercase letters only (26 chars)
  • Upper — Uppercase letters only (26 chars)
  • Digits — Digits only (10 chars)

🇮🇳 Incremental Mode — Hinglish

Incremental mode = Smart brute force! Normal brute force: a, b, c, d... bilkul alphabetically. JtR ka incremental mode: pehle sabse common characters try karta hai (e, t, a, o, i, n... — English mein yeh sabse zyada use hote hain). Toh aam passwords jaldi milne ki chance zyada hai!

Mask mode zyada powerful: Agar hume pata hai ki password format hai "4 lowercase + 4 numbers" (like "suresh123"), toh mask: ?l?l?l?l?d?d?d?d. Isse brute force space dramatically kam ho jaati hai!

⭐ Important Points

  1. Incremental = JtR's smart brute force using character frequency analysis.
  2. Mask mode (?l?u?d?s?a) dramatically reduces search space when pattern is known.
  3. --incremental=Digits is fastest — only 10 possible chars per position.
  4. Incremental mode is guaranteed to crack eventually — just a matter of time.
  5. JtR can be paused and resumed — it saves progress automatically.

Evil Twin Attack

5.5

😈 What is an Evil Twin Attack?

An Evil Twin Attack involves creating a fake wireless access point that mimics a legitimate AP — same SSID, same security type, often stronger signal. Victims unknowingly connect to the fake AP, allowing the attacker to perform:

  • Man-in-the-Middle (MitM): Intercept all traffic between victim and internet
  • Credential harvesting: Capture Wi-Fi password via fake login portal
  • SSL stripping: Downgrade HTTPS to HTTP to capture sensitive data
  • DNS spoofing: Redirect victim to fake websites

Airgeddon automates this with: deauth → clients disconnect from real AP → clients auto-reconnect → some connect to fake AP with stronger signal → captive portal asks for Wi-Fi password.

EVIL TWIN ATTACK FLOW: [Real AP: "HomeWiFi" ←→ Victim Device] ↓ Step 1: Attacker sends Deauth frames [Real AP: "HomeWiFi" ✗ Victim Device disconnected] ↓ Step 2: Attacker creates fake AP with same SSID [Fake AP: "HomeWiFi" (stronger signal)] ↓ Step 3: Victim auto-connects to stronger signal [Fake AP: "HomeWiFi" ←→ Victim Device (MitM!)] ↓ Step 4: Captive portal shown [Fake Login Page: "Enter WiFi password to reconnect"] ↓ Victim enters real password [Attacker captures: "HomeWiFi" password = "victim_password"]
🎯 Exam Point

Evil Twin attacks work because: (1) Devices auto-connect to familiar SSIDs, (2) Stronger signal wins the connection race, (3) Users trust familiar network names. Defense: Use certificate-based authentication (802.1X/WPA-Enterprise), verify AP certificates, use VPN on public networks.

⭐ Important Points

  1. Evil Twin = fake AP with same SSID as legitimate network.
  2. Uses higher signal strength to attract clients away from real AP.
  3. Typically combined with deauthentication attack to force clients off real AP.
  4. Captive portal presents fake login page to capture Wi-Fi credentials.
  5. Defense: WPA3, 802.1X enterprise, VPN usage on public networks.

Handshake Capture

5.6

🤝 WPA/WPA2 4-Way Handshake

When a client connects to a WPA/WPA2 network, a 4-way handshake occurs between the client and AP to establish encrypted communication. This handshake contains cryptographic material derived from the Wi-Fi password. Capturing this handshake allows offline cracking.

The 4-way handshake does NOT directly contain the password, but it contains a MIC (Message Integrity Code) that can be used to verify if a candidate password is correct — this is what JtR, hashcat, and aircrack-ng exploit.

Airgeddon captures handshakes by:

  1. Monitor mode → scan target network → lock to target channel
  2. Run airodump-ng to capture packets
  3. Send deauth frames to force clients to reconnect → triggering new handshake
  4. Capture the 4-way handshake in .cap file

🇮🇳 Handshake — Hinglish

4-Way Handshake = Device aur Router ke beech ka secret agreement! Jab phone WiFi se connect karta hai, toh 4 messages exchange hote hain — yeh proof hai ki dono ke paas sahi password hai. Yeh messages capture karke hum baad mein offline crack kar sakte hain!

Direct password nahi milta — ek verification token milta hai (MIC). Phir hum har possible password ka yahi token banaate hain aur match karte hain. Jab match ho — password mila!

⭐ Important Points

  1. WPA/WPA2 uses a 4-way handshake for authentication during connection.
  2. Handshake contains a MIC (Message Integrity Code) — not the actual password.
  3. Captured in a .cap file using airodump-ng.
  4. Deauth attack is used to force a new handshake without waiting for natural connection.
  5. Captured handshake can be cracked offline with aircrack-ng, hashcat, or JtR.

Deauthentication Attack

5.8

📵 How Deauth Attacks Work

A Deauthentication (Deauth) Attack exploits a vulnerability in the 802.11 Wi-Fi protocol. Management frames (including deauthentication frames) are unauthenticated in WPA2 — meaning anyone can send a fake deauth frame claiming to be from the AP, and clients will disconnect.

The deauth packet contains: Source MAC (spoofed as AP MAC), Destination MAC (client or broadcast FF:FF:FF:FF:FF:FF), Reason code (e.g., "Deauthenticated because station is leaving").

Effects: Disconnect clients → disrupt network service (DoS) → force handshake for capture → support Evil Twin attack by removing clients from real AP.

🎯 Exam Point

Deauth attack is possible because 802.11 management frames are not authenticated/encrypted in WPA2. WPA3 with Management Frame Protection (MFP/802.11w) prevents deauth attacks by authenticating management frames.

⭐ Important Points

  1. Deauth attacks exploit unauthenticated management frames in 802.11 WPA2.
  2. Fake deauth frames can be sent by any nearby device — no network access needed.
  3. Used to: (1) capture handshake, (2) support Evil Twin, (3) DoS attack.
  4. WPA3 + 802.11w (Management Frame Protection) defeats deauth attacks.
  5. Airgeddon uses aireplay-ng -0 internally for deauth attacks.

Captive Portal Attack

5.9

🌐 What is a Captive Portal Attack?

A Captive Portal Attack combines Evil Twin with a fake web page that asks victims to enter their Wi-Fi password to "restore connectivity." This is social engineering combined with technical attack. Airgeddon automates the entire process:

  1. Creates fake AP (Evil Twin) with same SSID
  2. Runs DHCP server (dnsmasq) to assign IPs to connecting clients
  3. Sets up DNS redirect — all DNS queries point to attacker
  4. Serves fake login page — "Your router needs configuration. Please enter your Wi-Fi password to continue"
  5. When victim enters password, it's saved and verified against the captured WPA handshake
  6. If password matches — attack successful! Real internet restored to victim.

Wi-Fi Deauthentication Attack

6.5

📵 How Deauth Attack Works on the Board

The Deauther Board's deauth attack works as follows:

  1. Board scans nearby Wi-Fi networks → lists all APs with their BSSIDs (MAC addresses)
  2. User selects target AP from web interface or OLED menu
  3. Board continuously sends deauthentication frames spoofing the AP's MAC address
  4. These frames tell connected clients: "The AP has disconnected you (Reason code 7: Class 3 frame received from nonassociated STA)"
  5. Clients disconnect and cannot reconnect as long as deauth frames are being sent

The key point: the board is NOT jamming RF signals (which would be illegal under FCC/DoT regulations). It is sending valid Wi-Fi frames — exploiting a protocol-level vulnerability.

DEAUTH ATTACK FLOW: [ESP8266 Board] | |── Scans: finds AP "TargetWiFi" (BSSID: AA:BB:CC:DD:EE:FF) | |── Sends: Deauth Frame (Source: AA:BB:CC:DD:EE:FF [spoofed], Dest: FF:FF:FF:FF:FF:FF [broadcast]) | Reason Code: 7 (Class 3 frame) | ↓ (Repeats 100x/sec) [All clients on "TargetWiFi"] ← "Deauthenticated by AP!" → Disconnect | └── Clients try to reconnect → Board sends another deauth → Disconnected again

🇮🇳 Deauth Attack — Hinglish

Deauth attack ki analogy: Socho tum office mein ho aur ek phone aata hai — "Security guard baat kar raha hai — sab log turant evacuate karein!" Sab log bahar chale jaate hain — bhale hi yeh prank call ho!

Client samjha: "Router ne disconnect kar diya." Woh reconnect karne ki koshish karta hai — board fir deauth bhejta hai — nahi ho paata connect!

Jamming nahi hai: Radio jammer RF signals block karta hai — illegal hai. Deauth board valid Wi-Fi frames bhejta hai — protocol exploit hai. Dono ka effect similar hai (disconnection) par mechanism alag hai.

⭐ Important Points

  1. Deauth attack sends forged deauthentication frames claiming to be from the AP.
  2. It is a protocol-level exploit, NOT RF jamming.
  3. Works because WPA2 does NOT authenticate management frames.
  4. Defense: Enable 802.11w / MFP on router; upgrade to WPA3.
  5. The board supports targeted deauth (specific client) and broadcast deauth (all clients).

Wireless Packet Capture

7.4

📦 What is Wireless Packet Capture?

Wireless packet capture involves recording all IEEE 802.11 frames transmitted in a given area. In Aircrack-ng, this is done using airodump-ng after putting the wireless adapter in monitor mode. Captured packets are saved to .cap files (compatible with Wireshark for analysis).

Types of data captured:

  • Beacon frames: AP announcements with SSID, BSSID, channel, encryption
  • Probe requests/responses: Clients searching for known networks
  • Authentication frames: WPA 4-way handshake exchange
  • Data frames: Encrypted user traffic
  • Management frames: Association, deauthentication, reassociation

WPA/WPA2 Password Cracking

7.7

🔓 How WPA Password Cracking Works

After capturing the WPA handshake, aircrack-ng performs a dictionary or brute-force attack offline. For each candidate password, it computes the PMK (Pairwise Master Key), then derives the PTK (Pairwise Transient Key), and finally computes the MIC. If the computed MIC matches the captured MIC — password found!

WEP Cracking

7.8

🔑 Why WEP is Completely Broken

WEP (Wired Equivalent Privacy) was the original Wi-Fi encryption standard introduced in 1997 with 802.11. It uses the RC4 stream cipher with a 24-bit Initialization Vector (IV). Due to its weak IV implementation, after collecting enough IVs (50,000–200,000), statistical analysis can recover the WEP key in minutes regardless of key length.

  • WEP uses RC4 cipher with weak IV implementation
  • IVs are only 24-bit — repeat quickly on busy networks
  • Statistical attacks (PTW, FMS, Korek) can crack any WEP key
  • WEP was officially deprecated by IEEE in 2004
  • No WEP network should exist today — all are critically vulnerable

(5) aireplay-ng --deauth 10 -a [BSSID] wlan0mon — in new terminal, send deauth to force client reconnect and trigger handshake. (6) Wait for "WPA handshake: [BSSID]" confirmation in airodump. (7) aircrack-ng -w rockyou.txt -b [BSSID] output-01.cap — run dictionary attack on captured handshake. This entire process only works on your own network in an authorized lab environment.

🍎 Why macOS Requires Specialized Testing

macOS has a unique security architecture that differs significantly from Windows and Linux. Security professionals need specialized knowledge and tools to test macOS defenses effectively:

  • MRT (Malware Removal Tool): Auto-removes known malware

Security researchers use frameworks like EvilOSX to test whether these protections can be bypassed in authorized scenarios, helping Apple and enterprises improve their defenses.

14-million-password wordlist from 2009 RockYou.com breach. Default wordlist on Kali Linux.
MFA / 2FA
Multi/Two-Factor Authentication — password + second factor (OTP). Defeats password-only attacks.
Account Lockout
Blocking login after N failed attempts. Primary defense against online brute force (Hydra).
Kismet
Passive wireless sniffer and IDS by Mike Kershaw (dragorn). Detects hidden SSIDs and rogue APs.
Monitor Mode (RFMON)
Wireless card mode that captures ALL frames in range — not just those addressed to your device.
SSID
Service Set Identifier — the human-readable name of a Wi-Fi network (e.g., "HomeWiFi").
BSSID
Basic SSID — the MAC address of an Access Point. Unique per physical device.
Rogue AP / Evil Twin
Unauthorized AP mimicking a legitimate one — same SSID — used for MitM attacks and credential theft.
PCAP
Packet Capture file format — used by Kismet, Wireshark, tcpdump for storing captured frames.
Beacon Frame
Management frame broadcast by AP every ~100ms containing SSID, BSSID, channel, encryption info.
John the Ripper (JtR)
Offline password cracker by Solar Designer (Alexander Peslyak). Supports 400+ hash types.
Password Hash
One-way cryptographic transformation of a password. Cannot be reversed — only verified by re-hashing.
Salt
Random data added to password before hashing. Prevents rainbow table and pre-computation attacks.
bcrypt
Intentionally slow password hashing algorithm. Work-factor makes brute force impractical.
unshadow
JtR utility that combines /etc/passwd and /etc/shadow into one file for cracking.
Word Mangling (--rules)
JtR transformations: capitalize, append numbers, leet-speak (a→@, e→3, o→0, i→1).
/etc/shadow
Linux file storing hashed passwords. $1$=MD5, $5$=SHA256, $6$=SHA512, $2a$=bcrypt.
Airgeddon
Bash-based wireless security framework by v1s1t0r. Menu-driven — Evil Twin, WPA, deauth attacks.
4-Way Handshake
WPA/WPA2 authentication exchange captured for offline password cracking with aircrack-ng.
Deauth Attack
Sending fake deauthentication frames to forcibly disconnect Wi-Fi clients. Exploits WPA2 weakness.
MIC (Message Integrity Code)
In WPA handshake, used to verify candidate passwords offline — not the password itself.
WPA3 / SAE
Current Wi-Fi security standard using Simultaneous Authentication of Equals. Resists offline attacks.
Captive Portal
Web page forcing authentication on network access. Faked in Evil Twin to steal Wi-Fi passwords.
802.11w / MFP
Management Frame Protection — authenticates management frames, defeating deauth attacks.
ESP8266
Low-cost Wi-Fi microcontroller by Espressif Systems. 2.4GHz only. Powers the Deauther Board.
Deauther Board
ESP8266-based device running Spacehuhn firmware for Wi-Fi management frame testing in labs.
Stefan Kremser (Spacehuhn)
Developer of the ESP8266 Deauther firmware — open source on GitHub.
Beacon Flood
Attack broadcasting hundreds of fake SSID beacon frames — creates illusion of many Wi-Fi networks.
NodeMCU
Most popular ESP8266 development board. Has built-in USB-Serial for easy firmware flashing.
Aircrack-ng
Wireless security suite by Thomas d'Otreppe. "-ng" = New Generation. 4 core tools in one suite.
airmon-ng
Aircrack-ng tool to enable/disable monitor mode and kill conflicting processes.
airodump-ng
Aircrack-ng packet capture tool — displays nearby networks in real-time and saves .cap files.
aireplay-ng
Aircrack-ng packet injection tool — deauth (mode 0), ARP replay (mode 3), injection test (mode 9).
WEP
Wired Equivalent Privacy — original Wi-Fi encryption (1997). Uses RC4. Completely broken since 2001.
IV (Initialization Vector)
Random value used with encryption key. WEP's 24-bit IV is too short — repeats causing statistical attack.
PMK / PTK
Pairwise Master Key / Transient Key — WPA key hierarchy derived from passphrase + SSID.
.cap file
Packet capture file from airodump-ng containing WPA handshake — used for offline cracking.
EvilOSX
Python-based macOS post-exploitation C2 framework for authorized security research only.
Post-Exploitation
Activities after gaining system access — persistence, privilege escalation, data collection, lateral movement.
C2 (Command & Control)
Server-agent architecture — researcher's server issues commands to agent on test machine.
EDR
Endpoint Detection and Response — security software (CrowdStrike, SentinelOne) detecting malicious activity.
SIP (System Integrity Protection)
macOS security feature protecting core system files — even root/admin cannot modify them.
Gatekeeper
macOS feature preventing execution of unverified/unsigned/non-notarized applications.
TCC
Transparency, Consent, and Control — macOS permission system for camera, mic, disk access.
Responsible Disclosure
Report vulnerability privately to vendor first; give 90 days to fix before public disclosure.
Red Team / Blue Team
Red = authorized attackers simulating threats. Blue = defenders detecting and responding.
DLP
Data Loss Prevention — tools and policies preventing unauthorized data exfiltration.
Least Privilege
Security principle: grant only minimum access needed — limits blast radius of any compromise.
SIEM
Security Information and Event Management — aggregates and analyzes logs for threat detection.
Penetration Testing
Authorized simulated cyberattack to evaluate security — always requires written signed agreement first.
IT Act 2000
India's primary cybercrime law. Section 43 & 66 cover unauthorized computer access — up to 3 years jail.
CFAA
Computer Fraud and Abuse Act — USA's primary cybercrime law. Unauthorized access is a federal crime.
