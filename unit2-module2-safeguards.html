Topic 01
Overview of Cyber Security Safeguards
01
Definition
Cyber Security Safeguards are the totality of technical controls, procedural measures, administrative policies, and physical mechanisms that an organisation deploys to protect its information assets from threats, reduce vulnerabilities, and ensure CIA — Confidentiality, Integrity, and Availability.
Hinglish Explanation
Module 1 mein humne sikha ki kya kya khatare hain aur vulnerabilities kahan hain. Ab Module 2 mein seekhenge ki un khataaron se kaise bachein. Jaise ghar ko secure karne ke liye tum lock lagate ho, CCTV lagate ho, alarm system lagate ho — same tarah digital world mein alag-alag safeguards lagate hain. Koi ek safeguard kaafi nahi hota — Defence-in-Depth chahiye.
Defence-in-Depth Model

Defence-in-Depth (DiD) is the principle of layering multiple independent security controls so that if one layer fails, others continue to provide protection. No single safeguard is a silver bullet — a determined attacker who defeats the firewall should still face authentication, then encryption, then monitoring, then audit logs.

🔧
Technical Controls
Firewalls, IDS/IPS, encryption, antivirus, access control lists, MFA, patch management — implemented in hardware or software.
📋
Administrative Controls
Security policies, procedures, awareness training, risk assessments, incident response plans — governing how people behave.
🏢
Physical Controls
Locked server rooms, badge access, CCTV, mantraps, biometric entry — preventing physical access to hardware and infrastructure.
The Security Control Triad
TypePurposeExamples
PreventiveStop the attack before it happensFirewalls, MFA, encryption, access control, patch management
DetectiveIdentify an attack in progress or after the factIDS, SIEM, audit logs, vulnerability scanning, UBA
CorrectiveMinimise damage and restore normal operations after an attackIncident response, backups, patch application, forensics

Topic 02
Access Control
02
Definition
Access Control is the selective restriction of access to a place, resource, system, or data. It determines who can access what, under what conditions, and what actions they are permitted to perform. It is the foundational mechanism enforcing the Principle of Least Privilege.
Hinglish Explanation
Access control ek darwaan (gatekeeper) ki tarah hai. Ghar mein darwaan decide karta hai ki kaun andar aayega aur kaun nahi. Digital world mein access control decide karta hai ki kaun konsi file, system, ya data access kar sakta hai. Ek finance employee HR records nahi dekh sakta, ek HR employee payroll calculations change nahi kar sakta — yahi access control hai.
The AAA Framework

Access control is built on three pillars — Authentication (prove who you are), Authorization (decide what you can do), and Accounting/Auditing (record what you did).

Access Control Models
👥DAC — Discretionary Access ControlFlexible▶

Definition: In DAC, the owner of a resource decides who can access it and what permissions they have. It is flexible but weak — if an owner misconfigures permissions or their account is compromised, excessive access is granted.

Example
Windows file system — ek file banane wala user decide karta hai ki "is file ko kaun read kar sakta hai, kaun edit kar sakta hai." File owner ne galti se "Everyone" ko write permission di — toh koi bhi employee file corrupt kar sakta hai. Risk: owner ki galti = everyone ki problem.

Real use: File system permissions (Linux chmod, Windows ACLs), Google Drive sharing.

🏛️MAC — Mandatory Access ControlHigh Security▶

Definition: In MAC, access decisions are made by the system/administrator based on security labels (classifications) assigned to both subjects (users) and objects (resources). Users cannot override or change these assignments — even file owners.

Each subject has a clearance level (e.g., Top Secret, Secret, Confidential, Unclassified) and each object has a classification label. The rule: you can only access objects at or below your clearance level.

Example
Indian Army mein ek Corporal ke paas "Top Secret" clearance nahi hai. Chahe wo kisi document ke folder mein physically ho — system automatically block kar dega access. Koi bhi officer usse permission nahi de sakta — system enforce karta hai. Ye government aur military systems mein use hota hai.

Real use: SELinux, military SCIF systems, government classified networks (NIPRNet/SIPRNet).

🏷️RBAC — Role-Based Access ControlIndustry Standard▶

Definition: In RBAC, permissions are assigned to roles, not directly to individual users. Users are then assigned to roles. This simplifies management enormously — changing a role's permissions instantly affects all users in that role.

Structure:

RBAC Structure:
Roles:
  Admin   → full system access
  Manager → read + approve + report
  Staff   → read + submit
  Auditor → read-only + logs

Users assigned to roles:
  Bhanu  → Admin
  Priya  → Manager
  Rahul  → Staff

→ Bhanu gets promoted: change role,
  not individual permissions

Advantages:

  • Scalable — adding new user = assign role
  • Consistent — same role = same access everywhere
  • Auditable — easy to review who has what
  • Least privilege enforced systematically
  • Separation of duties supported

Real use: Active Directory, AWS IAM roles, hospital EHR systems, banking apps.

📐ABAC — Attribute-Based Access ControlMost Flexible▶

Definition: ABAC makes access decisions based on attributes — of the user (department, clearance, location), of the resource (classification, project, owner), and of the environment (time of day, IP address, device type). This enables extremely granular, context-aware policies.

Example Policy in ABAC
"Allow access IF user.department = Finance AND user.clearance ≥ Level-3 AND resource.project = 'Q4-Audit' AND time = 09:00–18:00 AND device = corporate-managed." Ye sab conditions ek saath check hoti hain. RBAC se zyada powerful hai.

Real use: AWS IAM policies (condition keys), Zero Trust Architecture, modern cloud-native apps, GDPR-compliant data access systems.

Access Control Best Practices
Least Privilege enforcement Regular access reviews (quarterly) Immediate revocation on employee exit Separation of Duties (SoD) Just-In-Time (JIT) privileged access Privileged Access Management (PAM) Access request approval workflows Multi-person authorisation for critical actions

Topic 03
Authentication Techniques
03
Definition
Authentication is the process of verifying the identity of a user, device, or system before granting access. It answers the question: "Are you really who you claim to be?" Authentication is distinct from authorisation — authentication confirms identity; authorisation determines what that identity can do.
Hinglish Explanation
Authentication ek ID proof ki tarah hai. Jab tum bank jaate ho, bank employee tumse Aadhaar maangta hai — proof karo ki tum wahi ho jo bol rahe ho. Digital world mein authentication aise kaam karta hai. Sirf username batana authentication nahi hai — prove karna hoga: password, OTP, fingerprint, security key — kuch toh!
The Three Authentication Factors
🧠
Something You Know
Knowledge factor. Passwords, PINs, security questions, passphrases. Weakest factor — can be guessed, stolen, phished, or shared. Still the most widely used.
📱
Something You Have
Possession factor. Hardware token (YubiKey), authenticator app (TOTP), smart card, SMS OTP, phone. Physical device must be present — harder to steal remotely.
👁️
Something You Are
Inherence factor. Biometrics — fingerprint, face, iris, voice, typing cadence. Cannot be forgotten or easily stolen. Covered in depth in Topic 04 — Biometrics.
Authentication Methods — In Detail
🔑Password-Based Authentication▶

The most common but also the most attacked authentication method. Effectiveness is entirely dependent on password strength, uniqueness, and secure storage.

PracticeSecure ApproachWhy It Matters
Password lengthMinimum 12–16 charactersEach extra character exponentially increases crack time
StorageSalted bcrypt / Argon2 hash onlyPrevents rainbow tables; even DB breach doesn't reveal passwords
Rotation policyOnly when compromise suspected (NIST 800-63B)Forced rotation causes predictable patterns (Password1→Password2)
Breach checkingCheck against HaveIBeenPwned on creationPrevent use of already-leaked passwords
ManagerMandatory use of password managerEnables unique 20+ char passwords for every site
📲MFA — Multi-Factor AuthenticationCritical Control▶

MFA requires successful verification of two or more different factors. Even if an attacker steals a password, they still need the second factor. Microsoft research: MFA blocks 99.9% of automated account attacks.

TOTP — Time-Based One-Time Password:

# How TOTP works (RFC 6238)
1. Setup:  Server + App share a secret key
2. Every 30s:
   TOTP = HMAC-SHA1(secret, floor(time/30))
   → 6-digit code computed independently
      by both server AND authenticator app
3. Login:
   User enters password + 6-digit code
   Server recomputes → if match → access granted
   Code expires every 30 seconds
   Attacker needs secret key to predict next code

FIDO2 / Passkeys (Strongest):

Uses public-key cryptography. The private key never leaves the device. Authentication is:

  • Phishing-proof — bound to specific domain
  • Cannot be intercepted in transit
  • No server-side secret to breach
  • Works with biometric unlock on device
  • Supported by Google, Microsoft, Apple
🔏Certificate-Based Authentication (PKI)▶

Definition: Digital certificates issued by a trusted Certificate Authority (CA) authenticate users, devices, or servers. The certificate contains the entity's public key and is signed by the CA's private key. Used in TLS/HTTPS, smart cards, VPNs, and code signing.

1
User requests certificate from CA
Submits identity proof; CA validates and signs the certificate with its private key.
2
Server challenges the client
Server sends a random challenge. Client signs it with its private key.
3
Server verifies signature
Uses client's public key (from cert) to verify signature. If valid, authentication succeeds — no password needed.

Used in: HTTPS, client VPN authentication, SSH key-based auth, smart card login (government, military), IoT device identity.

🔄SSO — Single Sign-On & Federation▶

SSO allows a user to authenticate once and gain access to multiple independent systems without re-entering credentials. This improves user experience and reduces password fatigue — but creates a single point of failure if the SSO provider is compromised.

Hinglish Example
Jab tum "Google se login karo" button press karte ho kisi website pe — wo SSO hai. Ek baar Google pe login kiya, baaki websites Google ko trust karti hain aur bina password ke access deti hain. Enterprise mein Microsoft Entra ID (Active Directory) SSO use karta hai — ek corporate login se mail, Slack, Salesforce, SAP sab access.
SAML 2.0 — enterprise federation OAuth 2.0 — delegated access OpenID Connect (OIDC) — identity layer on OAuth Kerberos — internal Windows/AD authentication

Topic 04
Biometrics
04
Definition
Biometrics is the automated measurement and statistical analysis of people's unique physical or behavioural characteristics for authentication or identification purposes. Biometric traits are inherent to a person — they cannot be forgotten, lost, or easily shared.
Hinglish Explanation
Password bhool sakte ho, token kho sakta hai — lekin apni ungli ya aankhein toh saath hi hain! Biometrics tumhare body ke unique features use karta hai identity prove karne ke liye. Aadhar card mein fingerprint + iris scan — ye India ka largest biometric database hai (1.3 billion+). Tumhara phone ka face unlock ya fingerprint sensor — daily life biometrics example hai.

Continuous authentication uses behavioural biometrics — the system continuously verifies the user throughout the session, detecting if someone else has taken over the keyboard/mouse mid-session.

Key Biometric Performance Metrics
FAR — False Acceptance Rate
Probability that the system accepts an impostor. A low FAR is critical for security. FAR = 0.001% means 1 in 100,000 impostors gets through.
FRR — False Rejection Rate
Probability that the system rejects a legitimate user. High FRR causes user frustration and helpdesk calls. Trade-off: lowering FAR often raises FRR.
EER — Equal Error Rate
The threshold at which FAR = FRR. Lower EER = better system. Used to compare biometric systems — a system with EER of 0.1% is more accurate than one with EER of 1%.
Biometric Vulnerabilities & Limitations
🎭
Spoofing Attacks
Fake fingerprint (gelatin), 3D-printed face mask, voice synthesis (deepfakes) used to fool biometric sensors. Liveness detection (asking user to blink, move) is the countermeasure.
🔒
Irrevocability Problem
If a password is breached, you change the password. But if biometric data is stolen — you cannot "change" your fingerprint. This makes biometric database breaches extremely serious.
🌐
Cross-Border Privacy Laws
Biometric data is classified as "sensitive personal data" under GDPR, India's DPDP Act, BIPA (Illinois). Collecting it without explicit consent carries massive fines.
📊
Environmental Factors
Dirty or injured fingers, poor lighting (face recognition), background noise (voice), glasses (iris) — all degrade biometric accuracy in real-world deployments.

Topic 05
Audit and Logging
05
Definition
Audit and Logging is the systematic recording of system events, user actions, and security-relevant activities so that security teams can detect anomalies, investigate incidents, demonstrate compliance, and reconstruct the timeline of an attack. Logs are the "flight recorder" of a security incident — they tell you what happened, when, by whom, and from where.
Hinglish Explanation
Sochte hain CCTV camera — wo record karta hai ki kab kaun andar aaya, kya kiya, kab gaya. Audit logs exactly yahi karte hain digital systems mein. Login attempts, file access, admin commands, configuration changes, data downloads — sab kuch log hota hai. Agar koi breach hota hai toh log bataate hain "exactly kya hua" — jaise crime scene mein CCTV footage.
What Should Be Logged
🔑
Authentication Events
All login attempts (success and failure), logout events, password changes, MFA events, privilege escalation, account lockouts. Failed logins indicate brute-force; logins from new locations indicate compromise.
📁
Data Access Events
Who accessed what file/record, when, from where, what operation (read/write/delete). Critical for insider threat detection and data breach forensics.
⚙️
System & Config Changes
Firewall rule changes, user account creation/deletion, privilege grants, software installation, system reboots. Attackers often modify configs to maintain access.
🌐
Network Events
Connection attempts, DNS queries, data transfers (volume and destination), new listening ports, VPN connections. Useful for detecting C2 communication and data exfiltration.
SIEM — Security Information & Event Management

A SIEM aggregates logs from all sources — servers, firewalls, endpoints, cloud, applications — into a centralised platform. It normalises the data, correlates events across sources, applies detection rules, and generates alerts. SIEM is the "brain" of a Security Operations Centre (SOC).

Log Correlation Example
Single event: "User failed login" → low priority.
Correlated: "Same user failed login 300 times in 2 minutes from 50 different IPs" → SIEM alert: Distributed Brute Force Attack. No single log had the full picture.
Popular SIEM Platforms
Splunk — market leader, powerful query language (SPL).
Microsoft Sentinel — cloud-native SIEM + SOAR.
IBM QRadar — enterprise SIEM.
Elastic SIEM — open source option.
Chronicle (Google) — petabyte-scale logs.
Log Integrity & Retention

Logs are only useful if they are tamper-proof and retained long enough. Attackers often try to delete or modify logs to hide their tracks. Best practices: forward logs to a write-once remote SIEM immediately; use cryptographic log chaining (each entry hashes the previous one); retain logs for minimum 90 days online and 1 year archived (most compliance frameworks require this).

Centralised log collection (syslog, Fluentd) Immutable log storage (WORM — Write Once Read Many) Log integrity via cryptographic chaining NTP time synchronisation (for accurate timestamps) GDPR/PCI-DSS compliant retention periods

Topic 06
Deception Techniques
06
Definition
Deception techniques are security mechanisms that deliberately mislead attackers by presenting fake targets, decoy data, or fabricated environments — causing them to waste time and resources on traps while generating high-fidelity alerts that reveal their presence and methods.
Hinglish Explanation
Imagine karo ek museum jisme real paintings ke saath kuch fake paintings bhi rakhi hain — sensors se equipped. Chor jab fake painting churaane ki koshish kare, alarm baj jaata hai aur security ko pata chal jaata hai. Real painting safe rehti hai. Cyber deception exactly yahi karta hai — hackers ko fake targets pe attract karo, unhe detect karo, real systems safe rakho.
Honeypots

A honeypot is a decoy system intentionally designed to look like a legitimate, valuable target — but any interaction with it is by definition suspicious. Because no legitimate user or process should ever access a honeypot, every connection is a potential attacker.

🍯
Low-Interaction Honeypot
Emulates services (fake SSH, FTP, HTTP). Collects attacker IP, tool fingerprints, credentials tried. Low risk — no real OS for attacker to escape from. Used for mass threat intelligence collection. Tools: Honeyd, Cowrie.
🏗️
High-Interaction Honeypot
A real (but isolated) system the attacker can fully interact with. Provides deep behavioural intelligence — what commands do they run? What tools do they install? What persistence mechanisms do they use? Managed carefully to prevent it becoming a launchpad.
🕸️
Honeynet
A network of multiple honeypots simulating an entire enterprise environment — fake AD server, fake file server, fake workstations. Allows studying lateral movement behaviour of APT-level attackers across an entire fake organisation.
🍯
Honeytoken / Honey File
Fake data files (e.g., "Passwords_Backup.xlsx") with embedded tracking links or beacons. When an attacker opens the file — even from an air-gapped system — a callback is made revealing attacker location and identity.
Honeypot Use Cases in Enterprises
▶
Early Breach Detection
Deploy honeypots in internal network segments. Any scan or connection to the honeypot means an attacker is already inside — something perimeter defences missed. Zero false-positive alert rate.
▶
Threat Intelligence Collection
Study what vulnerabilities attackers are scanning for, what exploits they carry, what malware they deploy. This intelligence directly improves your defensive posture.
▶
Attacker Slow-Down
A well-decorated network with many fake assets forces attackers to investigate each one before moving on. This "noise" costs them time and increases detection probability.
Famous Honeypot Operation
Operation Buccaneer — Clifford Stoll's Hunt (1986)
The first famous honeypot usage — astronomer Clifford Stoll noticed a 75-cent accounting discrepancy in his computer at Lawrence Berkeley National Laboratory. He set up a fake "SDI network" honeypot to attract the intruder. Over 10 months, he traced a West German hacker (Marcus Hess) selling information to the KGB. This story, told in his book "The Cuckoo's Egg," defined the modern honeypot concept.

Topic 07
Denial of Service (DoS) Filters
07
Definition
DoS/DDoS Filters are systems, services, and configurations specifically designed to detect, absorb, or redirect malicious traffic designed to overwhelm and disable systems — distinguishing between legitimate and attack traffic at massive scale and blocking the attack while allowing normal users to continue accessing services.
Hinglish Explanation
DDoS attack mein enemy lakhs of cars ko ek road pe bhej deta hai — road jam ho jaati hai, real log nahi nikal sakte. DoS filters ek intelligent traffic management system ki tarah hain — fake cars (malicious traffic) ko identify karo aur alag raste bhejo, real cars (legitimate users) ko free passage do. Ye filtering DNS level se leke server level tak kaafi jagah hoti hai.
DoS/DDoS Defence Mechanisms
🌐CDN + Anycast ScrubbingLayer 3/4▶

CDN (Content Delivery Network) distributes traffic across hundreds of global points of presence (PoPs). A 1 Tbps attack hitting a single server would take it down instantly. That same 1 Tbps divided across 200 PoPs is only 5 Gbps each — easily absorbed. Cloudflare's network has 200+ Tbps of capacity.

Anycast routing assigns the same IP address to multiple geographically distributed servers. BGP routing automatically directs traffic to the nearest node. DDoS traffic is automatically distributed and absorbed globally.

CloudflareAkamai KonaAWS Shield AdvancedFastlyAzure DDoS Protection
⏱️Rate Limiting & Traffic ShapingLayer 7▶

Rate limiting restricts the number of requests a single IP address or user can make per second/minute. Legitimate users rarely hit these limits; automated attack tools do immediately.

# Nginx rate limiting configuration
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

server {
  location /api/ {
    limit_req zone=api burst=20 nodelay;
    # Max 10 requests/sec, burst of 20 allowed
    # 11th+ request → 429 Too Many Requests
  }
}

🤖Bot Detection & CAPTCHALayer 7▶

Modern bot detection analyses hundreds of signals: mouse movement patterns, keyboard behaviour, browser fingerprint, TLS fingerprint (JA3), HTTP header ordering, JavaScript execution timing. Bots exhibit mechanically perfect behaviour that differs from humans.

CAPTCHA (Completely Automated Public Turing test to tell Computers and Humans Apart) requires solving challenges that are easy for humans but hard for machines. Modern versions (reCAPTCHA v3) are invisible — scoring behaviour continuously without user interaction.

🚦BGP Blackholing & Traffic DiversionISP Level▶

BGP Blackholing (RTBH): During a massive volumetric DDoS, the victim instructs their ISP to drop all traffic destined for the attacked IP at the router level. The attacked resource becomes unreachable — but so does the attacker's traffic. A last resort when the attack volume exceeds scrubbing capacity.

Traffic diversion to scrubbing centre: Traffic is re-routed to a specialised scrubbing centre that filters malicious packets and forwards only clean traffic to the origin server. This allows the service to remain partially available even during large attacks.

Topic 08
Ethical Hacking
08
Definition
Ethical Hacking (Penetration Testing / White Hat Hacking) is the authorised, deliberate attempt to probe, test, and exploit vulnerabilities in systems, networks, or applications — with the explicit permission of the owner — for the purpose of identifying and fixing weaknesses before malicious actors find them.
Hinglish Explanation
Ek company apne ghar (system) ki security check karwaana chahti hai. Toh wo ek trusted chor (ethical hacker) ko hire karti hai — bolta hai "aao hamare ghar mein ghusne ki koshish karo, jo bhi jhiriya mile batao." Ye ethical hacker ghus jaata hai (ya ghusne ki koshish karta hai), sab vulnerabilities list karta hai, report deta hai — aur company fix karti hai. Permission + legal agreement = ethical hacking. Permission ke bina same kaam = criminal hacking.
The Penetration Testing Methodology (PTES)
1
Pre-Engagement & Scoping
Define scope (which systems can be tested), rules of engagement (what is off-limits), testing windows, emergency contact procedures. Sign a Statement of Work (SoW) and Rules of Engagement. Never skip this — working without written authorisation is illegal regardless of intent.
2
Reconnaissance (Information Gathering)
Passive: OSINT — LinkedIn, Shodan, DNS records, WHOIS, job postings (reveal technology stack), Google dorking. Active: Network scanning (Nmap), service enumeration, banner grabbing. Goal: build a complete map of the attack surface.
3
Vulnerability Analysis
Analyse gathered information to identify potential vulnerabilities. Use automated scanners (Nessus, OpenVAS) and manual review. Cross-reference against CVE databases. Prioritise by exploitability and impact.
4
Exploitation
Attempt to exploit discovered vulnerabilities — with restraint and care. Document evidence (screenshots, output logs) for the report. The goal is to prove exploitability, not to cause damage. Tools: Metasploit, Burp Suite, custom scripts.
5
Post-Exploitation & Pivoting
From the initial foothold, demonstrate realistic attacker behaviour — escalate privileges, access sensitive data, attempt lateral movement. Show the business impact of the vulnerability, not just its technical existence.
6
Reporting
Deliver a comprehensive report with: executive summary (for management), technical findings (for security team), risk ratings (CVSS scores), reproduction steps, and remediation recommendations. The report is the entire value of the engagement.
7
Remediation Verification
After the client fixes vulnerabilities, the ethical hacker re-tests to confirm the fixes are effective and haven't introduced new issues. Critical step often skipped — completing the security improvement loop.

Firewalls
09
Definition
A Firewall is a network security device (hardware or software) that monitors and controls incoming and outgoing network traffic based on a set of predefined security rules. It establishes a barrier between trusted internal networks and untrusted external networks, permitting legitimate traffic and blocking potentially harmful traffic.
Hinglish Explanation
Firewall ek chowkidar (security guard) ki tarah hai jo network ki boundary pe khada hai. Har packet jo andar ya bahar jaana chahta hai — chowkidar check karta hai: "kahan se aa raha hai? kahan ja raha hai? kaun sa port? allowed hai ya nahi?" Rules ke basis pe allow ya block karta hai. Ghar ke garam kamare aur baaki ghar ke beech jo aag rok ne wali deewar hoti hai — usi "fire wall" se ye naam aaya hai.

Types of Firewalls — Evolution
1️⃣Packet Filtering Firewall (Generation 1)▶

Inspects individual packets in isolation based on header fields: source/destination IP, source/destination port, and protocol (TCP/UDP/ICMP). Fast and simple, but has no awareness of connection state or application context.

# Example iptables packet filter rules (Linux)
# Allow established connections
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow SSH from specific IP only
iptables -A INPUT -p tcp --dport 22 -s 203.0.113.10 -j ACCEPT

# Allow HTTP and HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Drop everything else
iptables -A INPUT -j DROP

Weakness: Cannot distinguish between a legitimate connection response and a new unsolicited connection on the same port. Vulnerable to IP spoofing.

2️⃣Stateful Inspection Firewall (Generation 2)▶

Maintains a state table tracking all active connections. Instead of evaluating each packet in isolation, it checks whether the packet belongs to an established, legitimate connection. An unsolicited packet claiming to be part of an established connection is rejected — even if its header fields look valid.

This defeats many IP spoofing and session hijacking attacks. The state table records: source IP, destination IP, source port, destination port, TCP state (SYN, SYN-ACK, ESTABLISHED, FIN), and connection timeout.

Used in: Cisco ASA, pfSense, most enterprise perimeter firewalls. The standard for network-layer firewall protection.

3️⃣Application Layer Firewall / WAF (Generation 3)▶

Operates at Layer 7 (Application layer). Understands application protocols (HTTP, HTTPS, DNS, FTP, SMTP). Can inspect the actual content of traffic — detecting SQL injection in a URL parameter, cross-site scripting in a request body, or malware in an HTTP response.

A Web Application Firewall (WAF) is a specific application firewall placed in front of web applications. It applies OWASP Top 10 rules, custom policies, and ML-based anomaly detection to HTTP traffic.

Example
Traditional firewall: "Port 443 allow karo" — bas itna. WAF us allowed HTTPS request ko bhi X-ray karta hai: "Is URL mein ' OR 1=1 toh nahi hai? Is cookie mein koi script toh inject nahi ki gayi?" — application content level pe filtering.

4️⃣NGFW — Next-Generation Firewall (Generation 4)Modern Standard▶

NGFW combines stateful inspection + application awareness + deep packet inspection (DPI) + intrusion prevention (IPS) + SSL/TLS decryption + user identity awareness + threat intelligence feeds — all in a single device. It can identify which application is generating traffic, not just which port.

Topic 10
Vulnerability Scanning
10
Definition
Vulnerability Scanning is the automated, systematic process of identifying known security weaknesses in systems, networks, and applications by comparing their configurations and software versions against a continuously updated database of known vulnerabilities (CVEs). It provides a point-in-time snapshot of your security posture.
Hinglish Explanation
Vulnerability scanner ek doctor ki X-ray machine ki tarah hai jo tumhare poore network ka "health check" karta hai. Ye automatically puchta hai: "Is server ka Windows update hai? Is website mein SQL injection possible hai? Is router ka default password toh nahi chala raha?" Aur ek report deta hai: "Yahan 3 critical vulnerabilities hain, yahan 7 medium hain — pehle inhe fix karo."
Vulnerability Scanning vs Penetration Testing

Exploitation❌ Only identifies — does NOT exploit✅ Actually exploits to prove impact

CostLow — automated SaaS toolsHigh — skilled human hours
False positivesHigher — automated tools miss contextLower — human validates findings

Types of Vulnerability Scans
🌐
Unauthenticated (External) Scan
Scanner has no credentials — simulates an external attacker's view. Identifies services exposed to the internet, open ports, outdated versions visible from outside. Misses many internal vulnerabilities that require login to detect.
🔑
Authenticated (Credentialed) Scan
Scanner is given read-only credentials. Can log into systems and check installed software versions, registry settings, patch levels, user configurations. Far more accurate and complete than unauthenticated scans. Recommended for internal assessments.
🕸️
Web Application Scan (DAST)
Dynamic Application Security Testing — actively probes a running web app for OWASP Top 10 vulnerabilities: SQL injection, XSS, CSRF, broken auth, etc. Tools: OWASP ZAP, Burp Suite Pro, Acunetix, Veracode DAST.
📋
SAST — Static Code Analysis
Analyses source code without executing it — finds vulnerabilities in the code itself before deployment. Integrates into CI/CD pipelines. Tools: SonarQube, Checkmarx, Snyk. Catches issues like hardcoded secrets, SQL string concatenation, buffer overflow patterns.

CVSS is the industry-standard scoring system (0–10) for rating the severity of vulnerabilities, enabling organisations to prioritise remediation effort.

Topic 11
Security Policies
11
Definition
A Security Policy is a formal document that defines an organisation's security requirements, rules of behaviour, and responsibilities. It communicates what must be protected, why it must be protected, who is responsible, and what the consequences of non-compliance are. Security policies are the foundation of every technical safeguard — they provide the "why" and "what" while procedures provide the "how."
Hinglish Explanation
Security policy ek company ka constitution hai security ke liye. Jaise desh ka constitution bata ta hai ki nagrik ke rights kya hain aur kya nahi kar sakte — company ki security policy bata ti hai ki employees kya kar sakte hain, kya nahi, data kaise handle karein, breach hone pe kya karein. Bina policy ke technical controls ek direction ke bina hain — koi nahi jaanta ki kya allowed hai aur kya nahi.
Key Security Policy Documents
📱Acceptable Use Policy (AUP)▶

Defines what employees are permitted and prohibited to do with company IT resources — computers, internet, email, mobile devices. Typically covers: prohibition of illegal activity, personal use limitations, social media guidelines, data handling requirements.

Example AUP Clauses
"Corporate laptops shall not be used for personal cryptocurrency mining." | "Confidential data shall not be stored on personal cloud drives (Dropbox, personal Google Drive)." | "Employees shall not install unauthorised software on corporate devices." | "All company data transmitted externally must use approved encrypted channels."
🔑Password Policy▶

Defines minimum password complexity requirements, storage rules, rotation requirements, and MFA mandates. Should align with NIST 800-63B guidance: minimum 12+ characters, check against breach databases, MFA required for all privileged accounts, no mandatory rotation unless compromise is suspected.

ElementMinimum RequirementBest Practice
Length8 characters16+ characters or passphrase
ComplexityMixed case + numbersAdd symbols; use passphrases
MFAFor privileged accountsFor all accounts (mandatory)
ManagerRecommendedMandatory (corporate-managed)
Breach checkAt creationContinuous monitoring (HaveIBeenPwned API)
💻Remote Work & BYOD Policy▶

Defines security requirements for employees working from home or using personal devices for work. Critical components: mandatory VPN use for corporate resource access, approved device list, MDM (Mobile Device Management) enrollment requirement, prohibition of work data on unsecured personal devices, screen lock requirements.

Post-COVID, this has become one of the most important policies for organisations as remote work became permanent for many roles, dramatically expanding the attack surface beyond the corporate perimeter.

📊Data Classification & Handling Policy▶

Defines how different types of data must be classified (Public, Internal, Confidential, Restricted), stored, transmitted, shared, and disposed of. Encryption requirements for each classification. Sharing restrictions. Retention and disposal procedures (secure deletion, certificate of destruction for hardware).

🚨Incident Response Policy▶

Defines what constitutes a security incident, who must be notified and when, the escalation chain, the roles and responsibilities of the IR team, and the requirement to preserve evidence. Mandates timeliness of notifications — GDPR requires notification to supervisory authority within 72 hours of discovering a breach.

Every employee must know: Who do I call if I think I've been phished? What do I do if I find a USB drive? How do I report a suspicious email? The policy answers these questions.

Policy Lifecycle
1
Creation & Approval
Written by security team, reviewed by legal, HR, and business stakeholders, approved by CISO and executive leadership. Executive sponsorship is critical for enforcement.
2
Communication & Training
All employees trained on relevant policies at onboarding and annually thereafter. Attestation required — employees sign that they have read and understood the policy.
3
Enforcement & Compliance Monitoring
Technical controls enforce where possible (DLP tools, firewall rules). Audits measure compliance. HR enforces consequences for violations — from retraining to termination.
4
Review & Update
Policies reviewed at minimum annually and after significant incidents, technology changes, or regulatory updates. Outdated policies become compliance liabilities.

Topic 12
Threat Management
12
Definition
Threat Management is the continuous, proactive process of identifying, assessing, prioritising, and responding to cyber threats before they materialise into incidents — integrating threat intelligence, risk analysis, and operational response into a unified programme.
Hinglish Explanation
Threat management matlab sirf react karna nahi — pehle se anticipate karna. Jaise ek good army general sirf enemy ke attack ka wait nahi karta — wo pehle se intelligence gather karta hai ki enemy kahan hai, kya plan hai, aur apni defences accordingly position karta hai. Threat management exactly yahi karta hai cyber world mein — "aane wale attacks ki intelligence collect karo aur defences taiyaar karo."
Threat Intelligence (TI)

Threat Intelligence is evidence-based knowledge about existing or potential threats — including context, mechanisms, indicators, implications, and actionable advice — enabling informed decisions about responding to those threats.

Strategic TI
High-level trends for executives: "Nation-state attacks on financial sector have increased 40% this quarter." Informs budget and policy decisions. Not technical.
Operational TI
Specific upcoming campaigns: "APT28 is currently targeting Indian defence contractors via LinkedIn spear phishing." Informs security posture changes.
Tactical TI
Technical IOCs (Indicators of Compromise): specific IP addresses, domain names, file hashes, YARA rules. Directly imported into SIEM, firewalls, and EDR for automated blocking.
IOC vs IOA
IOC — Indicator of Compromise
Reactive — evidence that a system has already been compromised. Malicious IP/domain, malware file hash, known C2 URL, suspicious registry key. Used to detect ongoing or past breaches.
IOA — Indicator of Attack
Proactive — patterns that suggest an attack is in progress even without known IOCs. Unusual process spawning PowerShell, credential dumping behaviour, lateral movement patterns. Detects zero-days and novel malware.
The MITRE ATT&CK Framework

MITRE ATT&CK is a globally-accessible knowledge base of adversary tactics, techniques, and procedures (TTPs) based on real-world observations. It maps 14 tactical categories (from Initial Access to Impact) across hundreds of specific techniques. Security teams use it to:

🗺️
Threat Modelling
Map which ATT&CK techniques are most relevant to your organisation and industry, then verify you have detection coverage for each one.
🔴
Red Team Planning
Red teams use ATT&CK to design realistic attack simulations that mirror real adversary behaviour — not just generic pen tests.
📊
Coverage Analysis
Visualise your detection gaps — "We detect Initial Access well but have weak coverage of Lateral Movement techniques."
🔗
Threat Intelligence Mapping
Map threat actor TTPs to ATT&CK techniques, then verify your defences address those specific techniques.

Topic 13
Defending Against Malicious Software
13
Definition
Defending against malicious software involves deploying a layered set of technical controls, policies, and user behaviours that prevent malware from entering an environment, detect it when prevention fails, contain its spread, eradicate it from infected systems, and recover normal operations — following the prevent → detect → respond → recover lifecycle.
Hinglish Explanation
Malware defense sirf "antivirus install karo" nahi hai. Ye ek multi-layer strategy hai — jaise ek fort ke bahar paani ki khaai (network firewall), phir deewarein (email filtering), phir andar chowkidar (endpoint protection), phir safe vault (backup). Agar koi ek layer fail ho toh doosri rok le. Koi ek solution 100% malware nahi rok sakta.
The Anti-Malware Defence Stack
📧Email Security Gateway — Stop at the Door▶

The primary malware delivery vector is email — over 90% of malware arrives via phishing attachments or malicious links. Email security gateways inspect every incoming and outgoing email before it reaches the user's inbox.

Technical Controls:

  • SPF, DKIM, DMARC — anti-spoofing protocols; verify sender domain authenticity
  • Attachment sandboxing — execute suspicious attachments in isolated VM; observe behaviour before delivery
  • URL scanning — rewrite and scan all URLs at click-time, not just delivery
  • Anti-virus engine — scan attachments against signature database
  • ML-based phishing detection — analyse email header, body, sender reputation

Tools:

ProofpointMimecastMicrosoft Defender for Office 365Google Workspace SecurityBarracuda

Key metric: A well-tuned email gateway blocks 99.9%+ of malicious emails. The remaining 0.1% makes endpoint protection the next line of defence.

💻Endpoint Protection — EDR vs Traditional AV▶

Traditional Antivirus (AV) works by matching files against a signature database of known malware. It fails against: zero-day malware (no signature yet), polymorphic malware (changes its signature), and fileless malware (lives in memory — no file to scan).

EDR (Endpoint Detection and Response) overcomes these limitations through behavioural analysis. Instead of asking "is this file known-bad?", it asks "is this process behaving like malware?" — regardless of whether it's seen before.

# EDR behavioural detection examples:

# 1. Word spawning PowerShell (Living-off-the-land attack)
Alert: word.exe → cmd.exe → powershell.exe -enc [base64]
# Legitimate Word never spawns PowerShell → malware indicator

# 2. Credential dumping attempt
Alert: svchost.exe → accessing lsass.exe memory
# LSASS holds password hashes → Mimikatz pattern

# 3. Ransomware behaviour pattern
Alert: Process encrypting 500+ files/minute + deleting VSS shadow copies
# Auto-isolate host before ransomware spreads to network shares
CrowdStrike FalconSentinelOneMicrosoft Defender for EndpointCarbon BlackCybereason
🏝️Network Sandboxing & Zero Trust▶

A sandbox is an isolated, instrumented environment where suspicious files are detonated (executed) and observed — without risk to real systems. The sandbox records every action: files created, registry keys modified, network connections attempted, processes spawned. This behavioural profile determines whether the file is malware.

Analogy
Imagine ek bomb squad — suspicious package milta hai. Usse normal area mein nahi kholte — ek controlled, bomb-proof chamber mein kholte hain. Agar bomb tha — chamber safe rakhta hai. Cyber sandbox exactly yahi karta hai malicious files ke liye.
Palo Alto WildFireCuckoo Sandbox (open source)Any.runVirusTotalVMRay
💾Backup Strategy — The Last Line of Defence Against RansomwareCritical▶

A robust backup strategy is the ultimate defence against ransomware. Even if all prevention fails and ransomware encrypts everything — if you have good backups, you can recover without paying the ransom. The industry-standard backup strategy is 3-2-1-1-0:

3
3 copies of data
Primary data + 2 backup copies. Multiple copies protect against single-point failures.
2
On 2 different media types
E.g., internal drive + external tape/NAS. Prevents single-media failure destroying all copies.
1
1 copy offsite
Cloud backup or physical offsite tape. Protects against fire, flood, or physical theft of on-premise systems.
1
1 copy offline / immutable
Air-gapped or write-once (WORM) backup. Ransomware cannot encrypt what it cannot access or modify.
0
0 backup errors after testing
Regularly test restoration — "untested backups are not backups." 30% of backups fail during restore attempts (Veeam study).
🌐DNS Filtering, Web Proxy & Application Whitelisting▶

DNS filtering blocks connections to known malicious domains at the DNS resolution level — before any TCP connection is made. If a user's device attempts to resolve a known C2 domain, the DNS filter returns NXDOMAIN (domain not found), breaking the malware's ability to phone home.

Web proxy intercepts all web traffic, scanning for malware downloads, enforcing category-based URL policies, and inspecting SSL traffic.

Application whitelisting (allowlisting) only permits pre-approved executables to run on endpoints. Any unknown executable — including novel malware — is blocked by default. Most powerful but operationally complex to maintain.

Topic 14
Software Updates and Patch Management
14
Definition
Patch Management is the systematic process of acquiring, testing, and deploying software updates (patches) to systems, applications, and devices in order to remediate known security vulnerabilities, fix bugs, and maintain system stability — in a timely, controlled, and documented manner.
Hinglish Explanation
Har software mein bugs aur vulnerabilities aate rehte hain — yahi nature of software hai. Vendor patch release karta hai — ek fix. Ab us patch ko apne systems pe lagana patch management hai. Ye simple lagta hai lekin 100 servers, 1000 laptops, 50 alag software products ke saath — ye ek complex, critical operation ban jaata hai. WannaCry ransomware ne sirf un systems ko attack kiya jinpe 2 mahine purana patch nahi laga tha — patch hote toh attack nahi hota.

The Patch Management Lifecycle
1
Asset Inventory
You cannot patch what you don't know you have. Maintain a comprehensive, up-to-date inventory of all hardware, software, OS versions, and firmware across the entire environment. Tools: Qualys Asset Inventory, Lansweeper, ServiceNow CMDB.
2
Vulnerability Identification
Continuous vulnerability scanning (Nessus, Qualys) identifies which assets have unpatched CVEs. Integrate with patch management tool for automatic ticket creation when critical CVEs are found.
3
Patch Prioritisation (Risk-Based)
Not all patches are equal. Prioritise by: CVSS score, exploitability in the wild (CISA KEV catalogue), asset criticality, exposure (internet-facing vs internal). Critical CVEs on internet-facing systems = highest priority regardless of anything else.
4
Testing & Staging
Never deploy patches directly to production. Test in a staging environment first — patches occasionally break application compatibility. Follow change management process; schedule maintenance windows for critical systems.
5
Deployment
Use patch deployment tools for automated, scalable rollout. Deploy in waves: dev → test → staging → production. Monitor for errors during rollout. Maintain rollback capability for each patch.
6
Verification & Reporting
Post-deployment scanning confirms patch is applied. Generate compliance reports showing patch coverage percentage, mean time to patch (MTTP), and outstanding vulnerabilities. Required by ISO 27001, PCI-DSS, and most cyber insurance policies.

Enterprise Patch Management
Microsoft WSUS / SCCM / Intune — Windows endpoints. Red Hat Satellite — Linux servers. Jamf — macOS/iOS. Ivanti Patch — multi-OS. These tools push patches automatically on schedule, report compliance, and support rollback.

When You Cannot Patch — Compensating Controls

Sometimes patching is impossible — legacy systems with no vendor support, operational technology (OT/ICS) that cannot be taken offline, or critical applications that break when patched. In these cases, compensating controls reduce risk:

Network isolation / micro-segmentation Web Application Firewall rule blocking exploit pattern Disable vulnerable service/feature if not needed Intrusion Prevention System (IPS) virtual patching Enhanced monitoring and logging Application whitelisting
Patch Failure Case Study
WannaCry (2017) — 200,000 victims, $4 billion damage. Preventable with a 2-month-old patch.
Microsoft released MS17-010 (fixing EternalBlue — SMB vulnerability) on 14 March 2017. WannaCry launched on 12 May 2017 — 59 days later. Every organisation that applied the patch was safe. Every organisation that did not was hit. The NHS lost £92 million. FedEx lost $400 million. Maersk lost $300 million. This single event permanently changed how organisations approach patch management urgency — and remains the most cited argument for any cybersecurity budget request.
